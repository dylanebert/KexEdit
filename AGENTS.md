# KexEdit

KexEdit is the MIT FVD coaster editor. The live S0 surface is an ejected Vite + Svelte app: Vite owns `index.html` and `vite.config.ts`, `projectPlugin(".")` turns `shallot.json` into the plugin set, and `vite` serves the app. The view pane owns the one plain canvas; `View.svelte` starts Shallot in its mount effect and disposes the app in cleanup. `window.__harness` is the browser-check protocol, not a second UI surface. There is no iframe; any future overlay is reserved for in-view HUD content.

## Test Surface

The installed `shallot` bin is this project's runner; `check` and `workflow` call it directly. `test` and `list` go through `scripts/carrier.ts`, which holds one law the pinned runner does not: an integration selection that matches no row refuses. The runner refuses an empty `--requires`/`--subject` selection itself, but `test -- --integration --base <ref> --diff <ref>` with no changed subject runs the unit sweep and exits green, and `list` with that selection prints `0 checks` and exits zero; the wrapper turns both into a refusal, so the Chromium/GPU browser rows selected by changed subject never pass as an empty run. Delete the wrapper when the pinned runner refuses an empty diff selection. Every check is listed once in the root `shallot.json` authority. A subject is a file or directory path compared as its full token stream at both refs; a directory subject reads every file under it, so a row must not name a tree containing its own check file, and a glob matches no path and never selects.

Two named oracles sit outside both sweeps and run by claim with `bun run test -- --oracle "<claim>"`. `src/trajectory/convergence.oracle.ts` ("the march departs from the RK4 solution on constant ω or loses second-order convergence on varying intent") runs when an active spec changes the integrator step or its intent sampling. `src/trajectory/execution.oracle.ts` ("the H11 ratio times a resample of a trajectory other than the march it is reported against") runs when an active spec changes the march or resample kernel and needs the resample/march cost ratio on the 30-minute pooled ride.

## Shallot consumer contract

Its persisted application state is source staging, recorded with the complete SHA in `package.json` and `bun.lock`. Local co-development is uncommitted: record producer/consumer HEAD and dirt plus manifest/lock hashes, run `bun link` in the producer and `bun link @dylanebert/shallot --no-save` here, prove the installed realpath equals the producer, then exit with a fresh-empty-cache `bun install --force --frozen-lockfile --cache-dir <cache>`, a non-producer realpath, unchanged hashes and the focused gate. Source staging uses a fresh-empty-cache frozen install and proves installed metadata, full SHA, lock identity and no producer symlink or local directory. A stable published range is a later release exit, not this stage; saved `link:`/`file:` paths, short or moving refs, and local packs presented as staging are refused.

All commands use the installed carrier, never `node_modules/@dylanebert/shallot/scripts` or a checkout path. Browser presentation uses only the installed public `captureFrame` contract (`final-canvas 1280x720@1 rgba8-tight`) at a positively identified real adapter and fixed driver geometry; fallback or missing identity refuses. CPU path/trajectory properties stay unit claims and GPU buffer claims stay independent probes. Vite dedupes Shallot and TypeGPU; the `@dylanebert/shallot-grid` package remains the S1 registry plugin and is included only in identity/dedupe proof. Clean exit leaves manifest and lock byte-identical and reruns the focused product gate.

The shell keeps only the three pane surfaces, one canvas in the view, and the status line. It preserves the accepted geometry, responsive dimensions, empty regions, and one crisp one-pixel `#3c3836` divider at each internal seam, with no gaps, boxed pane borders, or outer shell ornament. The shell, look, and entrance decisions below are accepted S1 surface decisions.

The palette is grounded in the active custom Omarchy Gruvbox Dark theme on `omarchy`, at `/home/dylan/.config/omarchy/themes/gruvbox/colors.toml`. `omarchy theme current` reports `Gruvbox`; the file is generated by `scripts/omarchy-theme.ts` from the pinned `reference/gruvbox` source, so this is the applied seat data rather than a generic Gruvbox default. The shared role mapping is panes and shell lightest `#1d2021`; timeline is the 75/25 sRGB-derived step toward `#141617`, computed as `#1b1e1f`; and canvas is the next 75/25-derived step toward `#0d0e0f`, computed and scene-cleared as `#171a1b`. The accepted scene uses no tonemap. Divider `#3c3836`, grid `#504945`, foreground `#ebdbb2`, neutral red `#cc241d`, and neutral blue `#458588` remain the semantic roles below. Adobe Animate supplies timeline surface-order grammar only; Omarchy and the pinned Gruvbox supply the palette roles.

Sizing is responsive but bounded: the context pane is `clamp(16rem, 18vw, 24rem)`, the timeline is `clamp(12rem, 18vh, 18rem)`, and the view owns the remainder. At 2560×1440 those resolve to 24rem (384px) and 18vh (259.2px), with a 32px status line.

The viewport has no placeholder mesh. The world grid is the sole spatial referent. It is the registry plugin `@dylanebert/shallot-grid`, a `^0.1.2` dependency named `Grid` in `shallot.json`, shown by the scaffold scene's `<a grid />` on its defaults: `cells` 40 px per cell at a decade boundary, a `floor` of 1 m below which no finer decade draws, `xray` 0 so scene geometry hides the grid, `#504945` neutral lines, and 1 px axes as wide as the lines (a `#cc241d` X axis, a green Y axis at half alpha below the ground, a `#458588` Z axis) composited over the lines, with a horizon fade that scales with camera height. The boot row classifies the composited canvas for neutral lines, the red X and blue Z runs, and the green vertical run above the origin's projected screen position. `vite.config.ts` excludes the package from dependency prebundling, because a prebundled copy carries its own engine and never draws. The scene retains Shallot's established standard lighting components, ambient `0xd0dcec` plus directional `-0.4 -1 -0.55`, `0xfff4e0`, intensity `1.1`, as structural scene defaults rather than visible acceptance evidence.

The published range in `package.json` is what ships and what CI installs. To iterate on the grid without publishing, run `bun link` once in `projects/shallot-grid` and `bun link @dylanebert/shallot-grid` here. `resolve.dedupe` in `vite.config.ts` makes the linked plugin run on KexEdit's engine and typegpu rather than its own copies. `bun install --force` drops the link and returns to the registry; a plain `bun install` sees an unchanged lockfile and keeps the symlink. Publish only on release.

Before that splash, `View.svelte` performs the only S1 hard capability gate: a real `navigator.gpu.requestAdapter()` check. A missing adapter keeps the shell hidden and App settles a full-page blocking message; it does not start Shallot or wait for harness readiness. Capability outcomes are a small explicit pass-or-block shape with warning entries, so future screen-size, input, or peripheral heuristics can warn without blocking. No such thresholds are product claims here.

During supported boot, `View.svelte` passes the existing `shallotDark` loading screen a `document.body` container. Shallot therefore mounts its one existing splash overlay over the full page. `run()` resolves only after Shallot's loading completion and cleanup frame; `View.svelte` then waits for the first stepped harness frame before revealing the shell. `App.svelte` leaves the shell visible without motion for one painted splash-free frame, records that frame, and arms the pane entrance on the following frame. The four pane/status rectangles use one 180ms compositor-only scale/opacity animation from `scale(0.97)` and `opacity(0.72)` to identity/opacity `1`, eased with `cubic-bezier(0.16, 1, 0.3, 1)`; reduced motion disables it and restores the final state immediately. There is one canvas, one engine, no iframe, and no second splash. The browser row records splash absence at animation start, frame/timestamp ordering, an in-progress non-identity/partial-opacity sample, final identity/opacity, overlay geometry, clear-color samples, zero-gap/divider ownership, computed seam geometry and divider ownership, reduced-motion handoff, and a no-WebGPU blocking path.

## Ride and Timeline Contract

A ride is an entity. `RideHeader.length` is the authored integer tick count; its intent table has exactly that many rows. The march retains ticks `0..endTick`, so `count === endTick + 1`; `complete` ends at `length`, while `stalled` and `unsatisfiable` retain a shorter last-good prefix without changing authored length. Tick memory is sized from `ceil((length + 1) / CHUNK)`. The WebAssembly-memory-owning `Ride` stays in the entity-keyed side table rather than a typed-array component. `Train.ride` links each train to its ride, and train placement clamps to that ride's marched prefix.

Transport advances from scheduler `deltaTime`, never `elapsed`, without pausing or rescaling the engine. Playback always loops at authored length; the reserved component loop bit and hidden rate data are not visible controls. The timeline uses a seconds-domain viewport over `[0, 2 × authored duration]`. Frame-all fixes time zero at the left and puts authored duration 24 CSS px before the right edge; farther zoom-out reaches the unique full domain. Plain wheel zooms toward the cursor, Shift-wheel and Space/middle drag pan, ruler drag scrubs, and `F` frames all. A manual view survives resize in seconds; a fitted view recomputes its 24 px clearance.

Solved authored time uses the normal ground. A refusal keeps the last-good path, marks `endTick`, dims the unsolved authored tail through `length`, and holds/dims the train there. Post-end context begins at authored duration and uses the subtler hard-dark field; it is never authored or unsolved time. Status/notification presentation is deferred, so the status row stays empty.

## Path Contract

`src/path/` is the one artifact every later layer produces or consumes, and the shape the trajectory contract copies. A path is a CPU header `{ version, count, spacing, length, aux }`, a pose stream and an optional auxiliary stream. The pose is the typegpu struct `Pose { position: vec3f, w: f32, rotation: vec4f }`; its stride is `POSE_BYTES = d.sizeOf(Pose)` and lane offsets come from `d.memoryLayoutOf`, so no file in `src/path/` hand-types the stride or a WGSL struct, and `shader.ts` resolves the shader text from the schemas through `tgpu.resolve`. `w` is reserved zero. Arclength of pose `i` is `min(i * spacing, length)`: the stream is uniform, the last interval may be short, and `length` is the authored total. The local frame is Shallot's, right-handed with `-Z` forward, `+Y` up and `+X` right; `rotation` is a unit quaternion stored `(x, y, z, w)` in the sense of `Xform.quat` and rotates that frame into world; roll is derived, never stored. The auxiliary stream is a separate `array<vec4f>` buffer with `ceil(slots / 4)` rows per pose, absent when the header's slot map is empty; `auxSlot` resolves a name to row and lane on the CPU and the shader never sees names. `readPath` refuses a wrong version, a non-integer count, a non-positive spacing, a stream that is not a `Float32Array`, a stream whose length disagrees with the header, an aux stream that disagrees with the slot map, and a non-unit quaternion, each naming the field. Fixtures `straight`, `hill` and `helix` are closed-form curves sampled at `i * spacing` under `*.fixture.ts`, and every check compares a record to the curve rather than to the builder's arithmetic.

The view (`view.ts`) is a draw plugin: it owns the pose storage buffer published as `pathPoses`, the aux buffer as `pathAux`, and a `{ count, spacing }` uniform; one instanced draw of `count` instances expands a chord to the next pose in the foreground `#ebdbb2` and two ticks of length `spacing`, lateral `+X` in neutral red `#cc241d` and normal `+Y` in neutral green `#98971a`, as screen-constant-width quads, flat, unlit, depth-tested, in the `draw` group after `ColorSystem` and before `GlazeSystem`, with an atomic fragment probe as the browser witness. `setPath` validates through `readPath`, snapshots the header and copies both streams, and invalidates as one whole-buffer write per stream with the grow-and-republish idiom; a caller mutating its path afterwards reaches neither the upload nor the draw. `dispose` retracts only its own publications and resets the upload state. The scaffold scene loads the helix at boot through `path-view="fixture: helix"`; `View.svelte` exposes `window.__kexeditPath` for the browser row only. Lateral plus normal in the standard axis colors is the minimum that reads a full orientation.
