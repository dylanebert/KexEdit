# KexEdit

KexEdit is the MIT FVD coaster editor. The live S0 surface is an ejected Vite + Svelte app: Vite owns `index.html` and `vite.config.ts`, `projectPlugin(".")` turns `shallot.json` into the plugin set, and `vite` serves the app. The view pane owns the one plain canvas; `View.svelte` starts Shallot in its mount effect and disposes the app in cleanup. `window.__harness` is the browser-check protocol, not a second UI surface. There is no iframe; any future overlay is reserved for in-view HUD content.

## Test Surface

The carrier is native to this project. `test` runs the hermetic Svelte-compiler unit witness; `check` runs the manifest-authority surface check and `svelte-check`; `test:integration` selects the Chromium/GPU browser row by changed subject. Every check is listed once in the root `shallot.json` authority.

## Provisional S1 Look

The first looked-at pass was too busy, so the requested refinement removes persistent panel headers and speculative empty-state chrome. The shell keeps only the three pane surfaces, one canvas in the view, and the status line. Pane grounds are flat Gruvbox `#1d2021`; one-pixel `#3c3836` borders separate context, view, timeline, and status. These look decisions are provisional and have not received human acceptance.

The palette is grounded in the active custom Omarchy Gruvbox Dark theme on `omarchy`, at `/home/dylan/.config/omarchy/themes/gruvbox/colors.toml`. `omarchy theme current` reports `Gruvbox`; the file is generated by `scripts/omarchy-theme.ts` from the pinned `reference/gruvbox` source, so this is the applied seat data rather than a generic Gruvbox default. The measured hard-theme values used here are background `#1d2021`, dark background `#141617`, darker background `#0d0e0f`, dark1 divider `#3c3836`, dark2 grid `#504945`, foreground `#ebdbb2`, neutral red `#cc241d`, and neutral blue `#458588`. The camera clear color is the same `#1d2021`, so the viewport no longer carries the old blue-black `#0b0d10` field.

Sizing is responsive but bounded: the context pane is `clamp(16rem, 18vw, 24rem)`, the timeline is `clamp(12rem, 18vh, 18rem)`, and the view owns the remainder. At 2560×1440 those resolve to 24rem (384px) and 18vh (259.2px), with a 32px status line.

The viewport has no placeholder mesh. The GPU ground grid is the sole spatial referent: restrained warm-neutral minor and major lines, a softened Gruvbox neutral-red X axis, and a softened Gruvbox neutral-blue Z axis. Unity-like axis semantics apply only on the XZ ground plane; there is no visible Y line. The scene retains Shallot's established standard lighting components, ambient `0xd0dcec` plus directional `-0.4 -1 -0.55`, `0xfff4e0`, intensity `1.1`, as structural scene defaults rather than visible acceptance evidence.

During boot, `View.svelte` passes the existing `shallotDark` loading screen a `document.body` container. Shallot therefore mounts its one existing splash overlay over the full page. The shell remains layout-present but `visibility: hidden` until the installed harness reports its first stepped frame, then the shell is revealed. There is one canvas, one engine, no iframe, and no second splash. The browser row records the overlay geometry and splash SVG before readiness, then checks the ready handoff and flat grounds/borders after it settles.

Overall S1 acceptance remains pending.
